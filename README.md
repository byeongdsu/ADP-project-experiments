# ADP 프로젝트 실험 기록

ForzaETH 참조 스택에서 Pure Pursuit(PP)와 TinyLidarNet(TLN)의 문제를 관찰하고, 파라미터 변경을 통해 원인과 개선 방향을 검증한다.

## TLN 튜닝 최종 정리 — 2026-10-30

[EXP-007 최종 보고서](analyses/EXP-007/REPORT.md)에서 속도·EMA·코너 감속 튜닝과 남은 회피 한계를 정리했다. 장애물 2개 조건의 R13·R14는 속도가 달라도 같은 장애물 부근에서 충돌했다. [실행별 결과표](analyses/EXP-007/results_summary.csv)는 결과 JSON과 실행 YAML 기준이다. 아래 PP 중심 진행 상태와 10월 21일 인계는 과거 기록이다.

## 진행 순서
현재 상태: EXP-001(GT)과 EXP-002(PF)의 장애물 없는 조건 탐색 및 비교 분석을 완료했고, EXP-003~004의 장애물 주행과 EXP-006의 GT 대조 기록을 보존했다. EXP-005 고정 배치·진단 기능은 사용자 요청으로 원복했으며 과거 기록만 보관한다. 2026-10-26 추가 실행 결과도 runs/EXP-004에 포함한다. results.csv와 분석 보고서는 모든 실행을 아직 반영하지 않았으므로 개별 결과 JSON을 함께 확인한다. 다음 작업은 기존 bag의 오프라인 분석이며, 파라미터 변경이나 실험을 자동 실행하지 않는다.

1. 실행 중인 코드 버전, 맵, 컨트롤러, 위치 입력, 설정을 확인하고 기본값을 보존한다.
2. 기본 설정으로 시나리오를 실행하며 속도를 단계적으로 변경한다.
3. 재현되는 문제 후보를 고르고 원인 가설을 작성한다.
4. 관련 파라미터를 하나씩 변경하여 가설을 검증한다.
5. 대표 시나리오에서 개선 효과와 부작용을 확인한다.

## 시나리오
| ID | 장애물 수 | 위치 입력 |
|---|---|---|
| S1 | 0 | GT |
| S2 | 0 | PF |
| S3 | 1, 2, 4 | GT |
| S4 | 1, 2, 4 | PF |

각 시나리오를 PP와 TLN으로 실행한다. TLN이 GT/PF를 직접 사용하는지, 주변 모듈만 사용하는지 먼저 확인한다. 장애물 위치·크기도 저장한다. 속도 배율과 실제 속도를 구분한다.

## 파일
- `templates/run.md`: 개별 실험 기록 양식
- `runs/`: EXP-001부터 개별 기록 저장
- `configs/`: 실행 당시 설정 사본 저장
- `assets/`: 작은 이미지·그래프 저장
- `results.csv`: 전체 결과 비교표
- `findings.md`: 문제 후보·가설·검증 결과

관찰과 추정을 구분하고 미측정 값은 빈칸 또는 미측정으로 남긴다. 큰 영상과 rosbag은 외부 보관 후 링크를 기록한다. 외부 코드의 원본 라이선스를 보존하고 논문은 원문 링크로 기록한다.

## 첫 실험
PP / S1(장애물 없음 + GT) / 현재 기본 설정 / 안전한 낮은 속도로 실행한다. 현재 속도 배율과 설정을 먼저 확인하며 임의의 수치를 기본값으로 간주하지 않는다. 이후 TLN에서도 대응하는 기준 실험을 수행한다.
