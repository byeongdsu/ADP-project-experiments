# EXP-002 측위·추종 분석 방법

결론과 전체 수치는 [EXP-002 요약](../../runs/EXP-002/SUMMARY.md), GT 조건과의 대조는 [비교 보고서](../EXP-001-vs-002/REPORT.md)에 정리했다.

## 서로 다른 두 오차
**PF 측위 오차:** `/pf/viz/inferred_pose`와 `/car_state/odom_GT`의 XY 거리 및 래핑한 방향 차이를 계산한다. PF 표본마다 수신 시각이 이전인 최신 GT를 사용하고0.1초보다 오래된 GT는 사용하지 않는다. 센서 지연까지 제거한 동기화는 아니므로 실행 부하·topic 지연 영향이 포함된다.

**GT 실제 추종 거리:** 기록된 `/global_waypoints`의 인접점 선분에 실제 GT 위치를 투영하여 최소 거리를 계산한다. PF 위치로 계산한 Frenet d를 사용하지 않으므로 측위 오차와 실제 궤적 이탈을 분리할 수 있다. 선분 간격에 따른 근사 오차가 있으며 실제 차량 윤곽과 벽까지의 여유 거리 지표는 아니다.

각 실행의 PF 평균은 해당 구간 PF 표본의 산술평균, GT 실제 추종 평균은 해당 구간 GT 표본의 산술평균이다. 두 topic의 표본 수는 같지 않다. 성공 실행은3랩 계측 완료까지, 실패 실행은 첫 충돌 전까지 사용한다. 서로 다른 종료 구간을 단순 비교해 원인을 확정하지 않는다. GT/PF 비교 보고서는 이와 별도로 첫 주행의 같은 경로 구간을 공간 정렬했다.

## 초기화 정비 전후
최초 R01은 첫 주행 명령 이전에 위치3.909m·방향179.702도 오차가 있었고 첫명령+0.805초에 충돌했다. 이 실행은 초기 측위 실패로 보존한다. [실패 분석](../../runs/EXP-002/R01/README.md).

이후 시뮬레이터와 같은 알려진 출발 pose를 시작 prior로만 제공했다. 지역 입자 분산은 기존 위치표준편차0.5m/방향0.4rad를 유지했다. 초기화 정비 후 각 bag의 출발 전 표본은 정상적인 측위를 보였지만, `start_check.json`은 발견되지 않아 자동검사 통과 여부는 확인할 수 없다. [정비·테스트 기록](../../configs/pf_initialization_validation/README.md).

## 재현
ROS underlay와 작업공간 overlay를 source한 뒤 저장소 루트에서 다음 형식으로 실행한다.

```bash
python3 scripts/analyze_pf_run.py runs/EXP-002/R06 --start 1792494337.138501991 --end 1792494362.787375139
```

실행별 명령과 시각은 각 README 및 `pf_tracking_metrics.json`, scorer 근거는 `runtime_evidence.txt`에 있다. 원본bag에서 read-only 조회하고,지표와측위오차CSV를생성한다. 원본 .db3는 로컬에만 보존되어 재현 시 별도 준비해야 한다.

PP 파라미터 튜닝은 수행하지 않았다. 초기 측위 실패 정비와 주행 성능 개선 실험은 구분한다. 다음은 EXP-003~004의 기본 관찰이며, 추가적인 미세 배율 탐색은 보류한다.
