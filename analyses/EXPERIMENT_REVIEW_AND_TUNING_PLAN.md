# ADP 실험 경과와 후속 파라미터 검증 계획 — 초안

작성일: 2026-10-26. GitHub README·findings·EXP-001/002 비교 보고서와 로컬 SESSION_HANDOFF, results.csv, EXP-003/004/006 기록을 종합했다. GitHub 확인 당시 Issues는 없고 Discussions는 비활성 상태였다. 아래 후속 계획은 제안이며 실행 조건의 확정이나 튜닝 완료를 의미하지 않는다.

## 1. 연구 목적과 진행 방식

ForzaETH 참조 스택의 hyhall12 환경에서 Pure Pursuit(PP)의 실패 조건을 관찰하고, 위치 입력(GT/PF), 속도 배율, 장애물 조건의 영향을 구분한다. 관찰된 실패를 측위·경로 생성·상태 전환·경로 추종으로 나누어 원인 가설을 세운 뒤, 관련 파라미터를 하나씩 변경해 개선 효과와 부작용을 검증한다. TinyLidarNet(TLN) 비교는 향후 항목이며 현재 자료에서 수행 결과를 주장하지 않는다.

GT는 실제 위치 입력, PF는 입자 필터 추정 위치 입력이다. PF 조건에서도 실제 추종 성능은 GT 궤적으로 평가하고, PF-GT 측위 오차는 별도 지표로 기록한다.

## 3. 관찰에서 도출한 결과와 아직 남은 가설

### 3.1 장애물 없는 고속 주행

동일 경로의 공통 82개 구간을 비교한 실제 추종 거리의 공간 평균은 GT에서 0.75의 15.81cm → 0.85의 27.40cm, PF에서 11.94cm → 22.69cm로 증가했다. GT/PF 0.85 충돌점은 약 6.4cm 차이였다.

따라서 공통 제어·차량 동역학의 영향을 검증할 이유가 있다. 속도에 비례한 lookahead 증가와 제한적인 횡오차 감속은 후보지만 주원인은 미확정이다. PF 수치가 작은 일부 실행을 근거로 PF가 GT보다 우수하다고 일반화하지 않는다. 실제 내부 L1·목표점은 기존 bag에서 직접 측정되지 않았다.

### 3.2 장애물 두 개에서 정지

EXP-003의 상세 재구성에서는 두 번째 장애물이 전방 3m 검사 범위에 들어오고, 회피 경로와 장애물의 횡차이가 약 0.05m로 0.1m 점유 기준에 걸렸다. 로그의 O_FREE False 및 OVERTAKE → TRAILING 전환과 일치한다. TRAILING의 간격 제어는 정적 장애물 앞에서 속도를 0으로 제한하고, FTG는 비활성 상태였다.

핵심 문제는 가장 가까운 장애물 하나를 중심으로 만든 회피 경로와, 다른 장애물까지 확인하는 점유 검사의 관계다. 이 결과가 맵 전체에 통과 경로가 없다는 뜻은 아니다. 점유 임계값 완화만으로 해결됐다고 판단할 수 없다.

### 3.3 네 번째 배치의 충돌

EXP-004/R07-retry3은 충돌 0.3→0.2초 전 동일 s≈21.9m 부근의 local 경로 d가 -0.541→+0.472m로 약 1.01m 바뀌었다. 차량은 d≈-0.37m에 남았고, 충돌 50ms 전 명령 속도는 0이지만 실제 vx는 약 1.43m/s였다.

경로 급변·상태 전환·잔류 속도가 함께 관찰됐다. 정확한 방향 변경 트리거와 각각의 인과 기여는 아직 미확정이다. 새 planner 출력 자체가 바뀌었으므로 경로 캐시 하나만으로 원인을 설명하기 어렵다. 기존 3초 TTL은 단기 경로 보존이며 지난 랩 학습의 증거가 아니다.

## 4. 다음 검증 순서

1. **기존 bag 분석부터 완료한다.** GT 첫 배치와 PF 네 번째 배치에서 장애물 좌표·크기, 생성 경로, local 경로, 차량 위치, O_FREE, 상태, 명령·실제 속도를 시간순으로 대조한다. 최근 이전 수신 표본 결합과 실제 내부 콜백 시각의 차이를 명시한다. 누락된 results.csv 행은 원본 결과·로그 확인 후 보완한다.
2. **회피 문제의 변경 대상을 좁힌다.** 첫 장애물 통과 후 경로 복귀가 두 번째 장애물을 향하는지, 회피 대상 변경과 방향 변경 시점이 맞는지 확인한다. 여러 장애물 동시 고려와 방향 유지 규칙이 필요하다면 기존 파라미터 조정과 구분해 알고리즘 변경으로 제안한다.
3. **별도로 PP 고속 추종을 검증한다.** 장애물 없는 GT 조건에서 lookahead 계수 하나를 바꿔 제어 효과를 분리한다. 기존 완주 배율 0.75의 성능 유지와 실패 배율 0.85의 개선을 함께 평가한다. 새 속도 경계 탐색은 우선하지 않는다.
4. **GT 검증 후 PF로 비교하고 이후 TLN으로 확장한다.** PF 시작 검사와 실제 입력 확인을 유지하고, 동일 평가 구간·장애물 배치를 사용한다. 새 실행은 사용자와 조건을 정한 뒤 진행한다.

## 5. 수정해 볼 파라미터와 판정 기준

현재 인계값은 global_limit=0.70, m_l1=0.575, q_l1=0.04이다. 아래 값은 코드·설정에서 확인한 후보이며 다음 실행 직전 실제 로드값을 다시 확인한다. 제안 수치는 최적값이 아니다.

| 대상 | 현 기준값 | 변경 방향·예시 | 검증할 가설 / 판정 |
|---|---|---|---|
| PP `m_l1` | 0.575 | 첫 후보: 0.55, 필요 시 0.525. `q_l1` 등은 고정 | 속도 비례 lookahead를 줄이면 고속 코너 이탈이 줄어드는가? GT 경로 거리 평균·상위 95%·최대, 충돌, 조향 진동·변화율, 랩타임을 비교 |
| PP `q_l1` | 0.04 | `m_l1` 효과 확인 후 필요할 때 소폭 증감. 수치는 그때 결정 | 저속에서도 바뀌는 기본 lookahead가 추종·진동에 미치는 영향. 처음부터 두 계수를 함께 바꾸지 않는다 |
| PP `lat_err_coeff` | 0.10 | lookahead 검증 후 별도 실험으로 0.15, 필요 시 0.20 제안 | 횡오차가 커질 때 감속 강화가 이탈·충돌을 줄이는가? 실제 속도 감소와 랩타임 손실을 함께 확인 |
| spline `evasion_dist` | 소스 초기값 0.55m | 기존 bag의 장애물·벽 여유를 먼저 계산한 뒤 증감 방향 결정 | 횡방향 회피 여유가 두 번째 장애물 간섭을 줄이는가? 키우면 벽 여유가 줄 수 있어 단방향 확대를 처방하지 않는다 |
| spline `pre_apex_*`, `post_apex_*` | 소스 초기값 pre=(-4,-3,-1.5)m, post=(2,3,4)m | 첫 분석에서 복귀 구간 간섭이 확인된 경우 관련 제어점 하나의 조정부터 검토 | 회피 시작·복귀 위치가 연속 장애물과 충돌하는가? 전체 경로의 장애물·벽 여유와 곡률을 함께 평가 |
| 회피 방향 전환 제한 | 소스에 `abs(cur_d)>0.5`일 때 반대편 전환을 막는 조건 | 전환 트리거 확인 후 유지 조건·히스테리시스 설계 검토 | 현재 차량 d≈-0.37m의 방향 급변을 줄일 수 있는가? 현재 조건은 코드 상수이며 기존 ROS 파라미터처럼 취급하지 않는다 |

`L1=q_l1+v*m_l1`의 제한 전 계산에서 v=6m/s라면 기준 3.49m, m_l1=0.55는 3.34m, 0.525는 3.19m다. 이는 변경 규모를 보여 주는 산술 예시다. 실제 목표점에는 코드의 제한·보정이 추가되므로 주행 중 실제 L1이라고 단정하지 않는다.

`splini_ttl=3초`, O_FREE의 전방 3m·횡차이 0.1m, FTG 활성화는 첫 변경 대상으로 두지 않는다. 현재 증거만으로 캐시 만료나 검사 기준이 주원인이라고 확정할 수 없고, FTG 전환은 별도 동작을 추가한다. 다중 장애물 경로 생성의 한계를 단일 계수 튜닝으로 해결할 수 있는지도 따로 판단한다.

## 6. 실험 조건과 결과 기록 틀

조건을 확정한 후 한 번에 한 항목만 변경한다. 맵·출발 pose·위치 입력·배율·실제 장애물 XY/yaw/크기·랩별 배치·코드 버전을 보존한다. seed가 같아도 PF 난수와 실행 타이밍까지 같다고 간주하지 않는다. 원복된 고정 배치 기능을 다시 도입한다는 뜻은 아니다.

반복 검증 단계에서는 조건별 독립 실행 3회를 제안하되 연속 3랩과 구분한다. 장애물 조건은 네 번째 배치까지 포함할 수 있도록 4랩 완료·첫 충돌·연속 15초 정지 중 먼저 도달하는 시점을 종료 기준 후보로 삼는다. 15초 전에 기록이 끝나면 해당 기준의 정지 판정은 미충족으로 남긴다.

| 항목 | 작성 내용 |
|---|---|
| 문제·가설 | 어떤 구간에서 무엇이 실패했고, 변경이 왜 영향을 줄 것으로 예상하는가 |
| 변경 | 파라미터 이름 / 변경 전→후 / 나머지 고정 조건 / 실제 로드값 |
| 주행 결과 | 목표 랩 완료, 전체 완료 랩, 충돌 종류·시각·좌표, 정지 시간, 배치별 통과 여부 |
| 정량 비교 | 동일 구간 GT 추종 거리, PF-GT 오차, 실제 속도, 명령 속도, 랩타임, 경로 급변량·최소 장애물 여유 |

## 7. 보고서·발표에 사용할 수 있는 요약 문안

> 본 실험에서는 hyhall12 환경에서 Pure Pursuit의 속도 배율, GT/PF 위치 입력 및 장애물 조건에 따른 주행 실패를 관찰했다. 장애물이 없는 경우 GT와 PF 모두 대표 배율 0.75에서 3랩을 완주했으나, 0.85에서는 유사 코너에서 충돌하고 실제 경로 이탈이 증가했다. 장애물 두 개 조건에서는 첫 장애물 회피 경로가 두 번째 장애물의 점유 검사에 걸려 정지하는 현상을 확인했다. PF 0.70의 세 실행에서는 3랩 완주 후 네 번째 배치에서 충돌이 반복됐고, 그중 상세 분석 실행에서 충돌 직전 약 1m의 좌우 경로 급변을 관찰했다. 후속 단계에서는 기존 로그로 회피 경로 생성·전환의 원인을 좁힌 뒤, 장애물 없는 조건의 lookahead 및 횡오차 감속 파라미터를 각각 검증하고, 장애물 조건의 회피 형상·방향 유지 개선을 별도로 평가한다.
