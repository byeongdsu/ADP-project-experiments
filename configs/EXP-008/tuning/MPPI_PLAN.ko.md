기본 MPPI 튜닝 기준 V1

목표: GT·1m/s에서 레이스라인 추종과 장애물 회피를 반복해서 성공시키고, 25ms 제어 주기의 계산 여유를 확보한다.
SVG 추가 실험·PF·PP 대조·속도 상승은 이 단계에서 보류한다. 아래 수치는 이번 작업의 목표값이며 검증된 안전 기준이나 성공 확률 보장이 아니다.

1. 먼저 재현성
동일 seed·동일 입력의 4스레드 샘플 생성 50회가 모두 일치해야 한다.
별도 진단에서 원본은 50/50회 불일치, 1스레드는 0/50회 불일치였다.
스레드별 분포 객체를 사용하는 진단용 수정 사본은 1·4스레드 모두 0/50회 불일치였고 첫 직렬 샘플 해시도 원본과 같았다.
수정 사본은 diagnostics/sampler_repro_20261031에만 있고 현재 주행 solver에는 적용하지 않았다.
이 검사는 샘플 생성 문제를 분리 확인한 것이며 특정 충돌의 단일 원인을 증명하지 않는다.
원본 10개 solver 파일의 해시 불변을 확인했다. 기타 sampler 함수와 전체 solver 재현성은 별도 점검 대상이다.

2. 무장애물 추종 통과 목표
독립 실행 3회, 각 3연속 랩. 모든 실행에서 충돌 0, GT 최근접 waypoint 거리 평균 ≤0.15m / p95 ≤0.30m / 최대 ≤0.40m.
현재 계산하는 거리는 waypoint 점 거리다. polyline 오차와 혼동하지 않는다. 정의를 바꾸면 기존 자료도 같은 정의로 다시 계산한다.
현재 R02는 평균0.137m, p95약0.302m, 최대0.358m. 3랩 한 번의 관찰이며 p95 목표에 조금 못 미친다.

3. 장애물 회피 통과 목표
GT·1m/s·장애물2개·seed2026에서 독립3회×각3랩, 모든 실행 충돌0, 15초 지속 정지 없음.
실제 XY/yaw와 랩별 배치를 대조한다. 회피 중에는 경로에서 벗어나므로 위 추종 거리 제한을 그대로 적용하지 않는다.
차체 표면 여유·조향 포화·조향 변화는 보조 지표로 기록한다. 장애물 중심거리를 차체 여유로 대신하지 않는다.
현재 R03은2랩후벽충돌, R04는3랩무충돌로 이 반복 통과 기준을 충족하지 않는다.

4. 계산 시간 목표
각 실행의 controller callback p95 ≤20ms, 25ms 초과 비율 ≤1%. solver 시간도 따로 보존한다.
비실시간 Ubuntu에서 이 목표는 절대 deadline 보장이 아니다. 입력 누락·오래된 상태·기록 오류가 있으면 원인부터 점검한다.

5. 튜닝 방식
재현성 수정과 새 baseline을 분리 기록한 뒤 예측 상태30→45를 먼저 단독 비교한다. 이후 거리 비용, 방향 비용, 조향 분산을 한 항목씩 검토한다.
샘플1000·4스레드·속도1m/s는 우선 유지한다. 가중치를 높이는 것이 항상 개선은 아니다.
후보는 우선 한 번 관찰하고, 유망 후보만 위 독립3회 기준으로 확인한다. 실패 로그를 성공 실행과 섞어 숨기지 않는다.
설정과 코드 버전을 동시에 바꾼 결과를 파라미터 효과라고 해석하지 않는다.

6. 최종 검증
선택 설정을 고정하고 아직 튜닝에 쓰지 않은 seed2027·2028에서 각1회×3랩 관찰한다. 실제 배치는 기록한다. 지금 새 seed 시험을 자동 실행하지 않는다.
해당 결과로 다시 튜닝하면 그 seed는 더 이상 미사용 검증 조건이 아니다.
감속·정지 추가는 별도 실험으로 두며, 정지로 충돌을 막은 결과를 회피 성공으로 세지 않는다.

다음 작업은 진단용 난수 수정안을 별도 주행 버전에 반영·검증하고 새 baseline을 세우는 것. 현재 solver·실행 설정·기존 결과는 그대로 보존했다.
수치 기준: MPPI_CRITERIA_V1.yaml. 기존 실행 지표: current_baselines.json.

사용자 확정 진행 순서

1. GT·1.0m/s에서 기본 MPPI에 집중한다. PF와 SVG 추가 시험은 보류한다.
2. 먼저 별도 난수 수정본 repro_v1을 R05 무장애물 시험으로 확인한다. 이 시험에서는 수학 파라미터를 바꾸지 않는다. 코드 변경과 파라미터 효과를 분리한다.
3. 새 기준 버전에서 예측 범위 → 거리/방향 비용 → 조향 분산을 한 항목씩 검토한다. 범위 내에서 좋은 후보를 찾는 것이며 전역 최적값을 증명하는 작업은 아니다. 샘플 수와 lambda는 추종/회피 결과와 계산량을 본 뒤 필요할 때 별도로 검토한다.
4. 선택한 설정을 독립 반복으로 확인한 후 속도를 1.0 → 1.5 → 2.0m/s로 단계적으로 올린다. 속도 명령과 예측 속도장을 일치시키고 각 단계에서 무장애물 추종부터 다시 확인한다. 현재 어댑터의 초기 지원 상한은 2.0m/s다.
5. PP 기반 시스템과 같은 GT·지도·차량·출발점·실제 장애물 배치·속도 조건에서 비교한다. 기존 global_limit 값만 같다고 실제 속도 조건이 같다고 보지 않는다. 고정 속도 명령 비교와 실제 속도 차이를 기록한다.
   - 무장애물: GT 경로 거리 평균/p95/최대, 조향 변동, 랩타임, 계산 시간.
   - 장애물: 완료 랩, 벽/장애물 충돌, 지속 정지, 회피 궤적, 차체 표면 여유를 검토한다. 중심거리는 안전 여유가 아니다.
   - 현재 MPPI는 회피 계획과 추종을 함께 수행한다. 기존 spline planner·state machine·PP와의 비교는 시스템 비교다. 결과를 PP 추종기 하나만의 개선으로 표현하지 않는다.
   - solver 시간, 조향 controller 시간, 전체 입력→출력 지연은 측정 범위를 맞춰 구분한다.
6. 기본 MPPI의 선택 설정과 비교 조건을 고정한 후 SVG-MPPI를 검토한다. SVG 전용 설정과 추가 계산량을 따로 기록한다. 기존 S01 결과는 초기 관찰로 보존한다.

주행 시험은 사용자가 네 터미널에서 직접 실행한다. 기존 기록과 source는 덮어쓰지 않는다. 성공 한 번이나 연속 3랩을 독립 반복 3회로 세지 않는다. 위험시 감속/정지 정책 추가는 조향 회피 튜닝과 분리한다.

R06 체크포인트: 사용자 요청에 따라 무장애물 대신 GT·1m/s·장애물2개 조건을 이어감. repro_v1로 3랩 무충돌 완료, 독립 주행은 현재1회. 벽 가까운 회피·조향 변동이 남으며 추가2회 반복으로 새 기준의 반복성을 확인할 단계. 무장애물 시험으로 자동 전환하지 않는다. R06 REVIEW.ko.md 참고.
