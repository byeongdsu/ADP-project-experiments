## 확인된 사실
첫drive명령 이전의 최신PF·GT표본을 비교했다. GT=(10.832046,-0.502110),yaw20.9269도,vx0의고정출발점이다. PF=(7.178891,0.887947),yaw-159.3716도. 위치오차3.9087m,래핑한방향오차179.7015도. 따라서 주행이측위를처음부터망가뜨린것이아니라,잘못된측위가주행전에존재했다. 첫속도명령1.606m/s,조향0.2255rad.

base_system 시작로그global_limit=0.25,Frenet노드로그pose source=/pf/viz/inferred_pose확인. PF시작로그GLOBAL INITIALIZATION확인. PF는코드상전역무작위입자초기화로시작하고,시뮬레이터의start_pose.yaml을PF초기prior로자동전달하는구현은없다. /initialpose를받으면지역초기화가가능하지만같은토픽을시뮬레이터도받아실제차량을리셋한다.

## 판단과 다음 조치
이번은PF초기측위실패사례로보존하며정상초기화된PF추종기준이나PP속도한계로해석하지않는다. 180도반대해가안정화된정확한이유(지도모호성,센서모델,프레임등)는아직미확정이다. 전역초기화만으로주행전올바른해가보장되지않음을확인했다.

제가고정한것은시뮬레이터GT출발점이고PF초기화까지연결하지않았으므로초기화준비가불충분했다. 다음은컨트롤러가꺼진상태에서PF에동일한알려진초기pose prior를제공하고,정지상태의PF-GT위치/헤딩오차수렴을확인한후주행한다. 시작prior제공과주행중GT로계속위치를보정하는것은구분한다. /initialpose를쓸때는시뮬레이터리셋부작용때문에컨트롤러를반드시끄고수행한다.
